### Задание 3. Создание и запуск EC2 экземпляра (виртуальной машины)

Для запуска и настройки виртуальной машины используется сервис **Amazon EC2 (Elastic Compute Cloud)**.
Данный сервис предоставляет пользователю возможность создавать виртуальные серверы, управлять их конфигурацией, сетевыми настройками и безопасностью.

#### 1. **Открыть сервис EC2.**

   Необходимо в строке поиска AWS Management Console ввести `EC2` и выбрать данный сервис.
   Он используется для запуска и управления виртуальными машинами.

![image](https://i.imgur.com/V0CoUU3.png)

#### 2. **Выбрать в меню слева пункт** `Instances → Launch instances`.

   После этого откроется мастер создания виртуальной машины.

![image](https://i.imgur.com/8zWxcoL.png)

#### 3. **Заполнить параметры для запуска виртуальной машины:**

**3.1. Name and tags.**

   В поле имени указано значение `webserver`.
   Это имя используется для идентификации инстанса в консоли AWS.

**3.2. Application and OS Images (AMI).**

   В списке базовых образов выбрано **Amazon Linux 2023 AMI** — это современная и оптимизированная для AWS операционная система.

**3.3. Тип виртуального сервера (Instance type**) — `t3.micro`, который доступен в рамках **Free Tier**.

![image](https://i.imgur.com/di7lfF2.png)

**3.4. Key pair (ключевая пара).**

   Ключи используются для безопасного подключения к виртуальной машине по SSH.

- Выбрана опция **Create a new key pair**.
- Введено имя ключа `toni_keypair`.
- Тип ключа — **RSA**, формат файла — `.pem`.

    Необходимо нажать кнопку `"Create key pair"` и скачать файл с приватным ключом (расширение `.pem`). Сохранити его в надежном месте, чтобы потом использовать его при подключении.

![image](https://i.imgur.com/a9xcATF.png)

**3.5. Security group (группа безопасности)** Это набор правил, которые определяют, какой трафик разрешен к вашему экземпляру.

   Создана новая группа с именем `webserver-sg`, которая определяет правила входящего трафика (Inbound rules).
   Добавлены два правила:

- Разрешён входящий **HTTP**-трафик (порт 80) с любого IP-адреса.
- Разрешён входящий **SSH**-трафик (порт 22) для удалённого доступа.

**3.6. Network settings.**

   Настройки сети (VPC и Subnet) оставлены по умолчанию, что позволяет AWS автоматически создать виртуальную подсеть для инстанса.

![image](https://i.imgur.com/E4BTW4I.png)
![image](https://i.imgur.com/YLQ8zoU.png)

**3.7. Configure Storage.**

    Оставлены настройки по умолчанию.

**3.8. Advanced details → User Data.**

В блоке **User Data** вставлен следующий скрипт, который автоматически устанавливает и запускает веб-сервер `NGINX` при первом запуске виртуальной машины:

```bash
   #!/bin/bash
   dnf -y update
   dnf -y install htop
   dnf -y install nginx
   systemctl enable nginx
   systemctl start nginx
```

![image](https://i.imgur.com/BsQw793.png)

Этот скрипт обеспечивает установку необходимых пакетов и автоматический запуск сервиса.

   > **Что такое User Data и какую роль выполняет данный скрипт? Для чего используется nginx?**
   > 
   > **User Data** — это специальный раздел при создании инстанса EC2, куда можно добавить команды или скрипт (обычно bash), который автоматически выполняется при первом запуске виртуальной машины.
   > Он используется для автоматической настройки окружения — установки программ, обновлений и конфигураций без ручного вмешательства пользователя.
   > В данном случае скрипт выполняет обновление системы и установку `NGINX` — это популярный веб-сервер, который принимает HTTP-запросы от пользователей и отдаёт им веб-страницы.
   > Он может также работать как **обратный прокси-сервер** и **балансировщик нагрузки**, обеспечивая быструю и стабильную работу сайтов и веб-приложений.
   > В лабораторной работе он используется для демонстрации успешного запуска сервера AWS EC2.

### Задание 4. Логирование и мониторинг

**Мониторинг** — это важная часть обеспечения надёжности, доступности и производительности экземпляров **Amazon EC2**.
AWS предоставляет встроенные инструменты для отслеживания состояния, логирования и анализа метрик — **Status checks**, **CloudWatch Monitoring** и **System Log**.

#### 1. Проверка статуса экземпляра (Status checks)

На вкладке **Status checks** выполняются автоматические проверки состояния инстанса.

- **System reachability check** — проверяет инфраструктуру AWS (физический хост, гипервизор).
- **Instance reachability check** — проверяет доступность операционной системы.

Для корректно работающего экземпляра обе проверки должны завершиться успешно —
**“3/3 checks passed”**, что говорит о стабильной работе виртуальной машины.

![image](https://i.imgur.com/UtH4BR0.png)

#### 2. Мониторинг с помощью Amazon CloudWatch

На вкладке **Monitoring** отображаются графики с ключевыми метриками EC2:

- загрузка CPU,
- сетевой трафик (входящий и исходящий),
- операции ввода-вывода и др.

Так как инстанс был создан недавно, метрик пока немного.
По умолчанию включён базовый мониторинг (**Basic monitoring**) — данные отправляются в CloudWatch каждые 5 минут.
При необходимости можно включить детализированный мониторинг (**Detailed monitoring**) — метрики будут отправляться каждую минуту.

> **Когда стоит включать детализированный мониторинг?**
> 
> В случаях, когда требуется точный анализ производительности (например, при работе нагруженных серверов, балансировке нагрузки или расследовании инцидентов).

![image](https://i.imgur.com/lcSQZin.png)

Можно нажать на иконку с тремя точками на любом графике и выбрать `Enlarge`, чтобы открыть метрику в развёрнутом виде.

![image](https://i.imgur.com/yZAfdgl.png)

#### 3. Просмотр системного лога (System log)

Для анализа загрузки и диагностики ошибок можно открыть системный лог экземпляра.
Для этого необходимо выбрать пункт меню:

![image](https://i.imgur.com/UCGqkkt.png)

### Задание 5. Подключение к EC2 инстансу по SSH

#### 1. Подготовка среды для подключения

Сначала необходимо открыть терминал (в Windows — PowerShell) и перейти в каталог, где хранится приватный ключ `.pem`.

#### 2. Проверка прав доступа к ключу

Для обеспечения безопасности SSH-подключения приватный ключ должен быть доступен **только текущему пользователю**.
Если права доступа к файлу слишком широкие, система отклонит подключение.

Для настройки прав:

- Кликнуть правой кнопкой мыши по файлу `.pem`;
- Открыть **Свойства → Безопасность**;
- Убедиться, что доступ есть только у вашей учётной записи Windows;
- Удалить разрешения для «Все» (Everyone) и других пользователей.

![image](https://i.imgur.com/CGVufSc.png)

#### 3. Подключение по SSH

Выполняется команда подключения:

```bash
ssh -i toni_keypair.pem ec2-user@35.158.121.224
```

где:

- `-i` — путь к приватному ключу,
- `ec2-user` — стандартный пользователь Amazon Linux,
- `35.158.121.224` — публичный IP-адрес инстанса EC2.

После подключения открывается терминал удалённого сервера.

#### 4. После успешного подключения видно приглашение командной строки:

```bash
[ec2-user@ip-172-31-35-203 ~]$
```

#### 5. Проверка работы веб-сервера

Для проверки работы сервиса `NGINX` можно выполнить команду:

```bash
sudo systemctl status nginx
```

![image](https://i.imgur.com/tL0M45y.png)

Если сервер работает корректно, отображается статус `active (running)`.

> **Почему в AWS нельзя использовать пароль для входа по SSH?**
> 
> Это сделано из соображений безопасности: пароль можно подобрать, а приватный ключ `.pem` уникален и используется только его владельцем.
> Такой подход исключает возможность взлома brute-force и обеспечивает безопасную авторизацию.

#### 6. Настройка NGINX

Создаём конфигурационный файл `nginx/default.conf`, который задаёт поведение веб-сервера:

```bash
mkdir -p nginx
cat > nginx/default.conf << 'NGINX'
server {
    listen 80;
    server_name _;
    root /var/www/html/public;
    index index.php index.html;

    location / {
        try_files $uri /index.php?$query_string;
    }

    location ~ \.php$ {
        include fastcgi_params;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        fastcgi_pass php:9000;
        fastcgi_index index.php;
    }

    location ~* \.(css|js|jpg|jpeg|png|gif|ico|svg|woff2?)$ {
        try_files $uri =404;
        expires max;
        access_log off;
    }
```

### Задание 7. Завершение работы и удаление ресурсов

#### 1. Остановка виртуальной машины (EC2 instance)

После завершения развёртывания приложения необходимо остановить работающий инстанс EC2, чтобы избежать начисления затрат.

Для этого используется команда AWS CLI, указывающая ID инстанса и регион:

```bash
aws ec2 stop-instances --instance-ids i-02c0a5b95555a2bbd --region eu-central-1
```

После выполнения команда возвращает JSON-ответ со статусом остановки:

![image](https://i.imgur.com/tgwmG6r.png)

#### 2. Проверка в AWS Console

В AWS Management Console (раздел **EC2 → Instances**) можно убедиться, что инстанс действительно остановлен.
Столбец Instance state показывает состояние `Stopping`, а затем серое `Stopped`.

![image](https://i.imgur.com/GYBdhaO.png)

> **Отличие между “Stop” и “Terminate”:**
>
> Команда **Stop** останавливает виртуальную машину (инстанс), но **не удаляет её данные**. Все настройки, тома EBS и IP-адрес (если он не был временным) сохраняются, и инстанс можно снова запустить позже.
>
> Команда **Terminate** полностью **удаляет инстанс и все связанные ресурсы**, включая хранилище и настройки сети. После этого восстановить машину невозможно.
>
> Таким образом, **Stop** используется для временной приостановки работы без потери данных, а **Terminate** — для полного удаления ресурса.
