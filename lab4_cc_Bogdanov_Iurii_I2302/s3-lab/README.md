# Лабораторная работа №4. Облачное хранилище данных. Amazon S3

## Цель работы

Целью работы является ознакомление с сервисом Amazon S3 (Simple Storage Service) и отработка основных операций:

- создание публичного и приватного бакетов;
- загрузка и организация объектов;
- работа с S3 через AWS CLI (копирование, перемещение, синхронизация);
- настройка версионирования и шифрования;
- использование S3 Static Website Hosting;
- применение Lifecycle-правил для архивирования старых данных.

После выполнения работы студент:

- понимает концепцию объектного хранилища и его отличия от блочного и файлового;
- умеет создавать и настраивать бакеты в Amazon S3;
- владеет навыками загрузки и управления объектами через консоль и CLI;
- знает, как настроить статический веб-хостинг на базе S3;
- понимает принципы версионирования и жизненного цикла объектов в S3.

## Условие

_Amazon S3_ — это объектное хранилище AWS, предназначенное для хранения файлов любого типа: изображений, резервных копий, документов, логов и т.д. Каждый объект хранится внутри _бакета_ (bucket) и имеет _уникальный ключ_ (key). "Папки" в консоли — это лишь префиксы ключей, а не настоящие директории.

В этой лабораторной будут созданы два бакета:

- _Публичный бакет_ - для хранения аватаров пользователей и статического контента;
- _Приватный бакет_ - для логов и служебных файлов (с Lifecycle-политикой).

## Ход выполнения работы

### Шаг 1. Подготовка среды

1. Необходимо войти в **AWS Management Console**, в правом верхнем углу убедиться, что выбран регион **Frankfurt (eu-central-1)**.
   Выбор региона важен, потому что имена бакетов в S3 **глобальные**, и в разных регионах могут быть заняты разные имена.

2. Формат имён бакетов:

- _Публичный_: `cc-lab4-pub-kXX`
- _Приватный_: `cc-lab4-priv-kXX`

3. Локально (на своем компьютере) необходимо создать структуру каталогов и файлов, как показано ниже:

```bash
    s3-lab/
    ├── public/
    │   ├── avatars/
    │   │   ├── user1.jpg
    │   │   └── user2.jpg
    │   └── content/logo.png
    ├── private/
    │   └── logs/
    │       └── activity.csv
    └── README.md
```

> Данные файлы в дальнейшем будут загружены в соответствующие бакеты.

### Шаг 2. Создание бакетов в Amazon S3

В рамках задания создавались **два бакета** в регионе `eu-central-1 (Frankfurt)`:

1. публичный бакет — `cc-lab4-pub-k01`;
2. приватный бакет — `cc-lab4-priv-k01`.

При этом **осознанно был выполнен вариант B** —
**“Object Ownership: Bucket owner enforced (ACLs disabled)”**.
Это современный и более безопасный способ работы с S3, при котором **ACL полностью отключаются**, а доступ регулируется **только через IAM и Bucket Policy**. Такой подход сейчас считается “правильным” в реальных проектах.

#### Создание публичного бакета

1. В консоли AWS перейти в раздел **S3** → **Create bucket**.

![image](https://i.imgur.com/Z3oGXgK.png)

2. Указать имя бакета (с учётом уникальности имён в S3):

   - **Bucket name**: `cc-lab4-pub-kXX`

    (было выбрано `k01` , потому что имя с `k1` было занято)

3. **Region**: `eu-central-1`.

4. В блоке **Object Ownership** выбрать:

   - **`Bucket owner enforced (ACLs disabled)`**

5. В блоке **Block Public Access** на этом шаге **намеренно оставить включённым** `Block all public access`, т.к. публичность будет настраиваться позже через **Bucket Policy**.

6. Нажать **Create bucket**.

После этого в списке бакетов появился бакет:

- `cc-lab4-pub-k01` — публичный по назначению, но пока ещё **не открыт в интернет**, т.к. публичный доступ заблокирован настройками BPA.

![image](https://i.imgur.com/xX2nkgr.png)

#### Создание приватного бакета

Аналогично необходимо создать второй бакет для служебных файлов и логов:

1. **Create bucket**
2. **Bucket name**: `cc-lab4-priv-k01`
3. **Region**: `eu-central-1`
4. **Object Ownership**: снова выбрать
   **`Bucket owner enforced (ACLs disabled)`**
5. **Block public access**: оставить включённым
6. **Create bucket**

![image](https://i.imgur.com/jPLCfWb.png)

Таким образом, после выполнения шага были созданы два бакета:

- **`cc-lab4-pub-k01`** — для `avatars/` и `content/`
- **`cc-lab4-priv-k01`** — для `logs/` и служебных данных

Оба бакета работают в режиме **“ACL отключены”**, что означает:

- все загружаемые объекты **автоматически принадлежат владельцу бакета**;
- доступ к объектам **не настраивается через ACL**, только через IAM и Bucket Policy;
- это исключает проблему “объект загрузил другой аккаунт → владелец не может удалить”.

> **Вопрос:**
>
> Чем отличаются два способа управления доступом к бакетам в S3?
>
> **Ответ:**
>
> В Amazon S3 существует два основных способа управления доступом:
>
> 1. **Через ACL (Access Control Lists)** — устаревший, объектно-ориентированный способ, где права задаются отдельно для каждого файла или бакета. Он менее безопасен и сложен в управлении, особенно при большом количестве объектов.
> 2. **Через Bucket Policy и IAM-политики** — современный и рекомендуемый подход, основанный на централизованных политиках доступа. Все разрешения задаются на уровне учётных записей и ролей AWS, а не объектов.
>
> Основное отличие заключается в том, что **ACL позволяют управлять доступом к отдельным объектам**, а **Bucket Policy и IAM обеспечивают централизованное управление безопасностью**.
>
> В данной лабораторной работе использовался **современный вариант — Object Ownership: Bucket owner enforced**, при котором ACL полностью отключены, а все разрешения реализованы через **IAM и Bucket Policy**, что обеспечивает большую безопасность и контроль.

> **Вопрос:**
>
> Что означает опция “Block all public access” и зачем нужна данная настройка?
>
>**Ответ:**
>
>Опция **“Block all public access”** в Amazon S3 полностью запрещает публичный доступ к бакету и его объектам из интернета.
Она защищает данные от случайного раскрытия, даже если в бакете есть публичные политики или ACL.
Когда эта опция включена — никакие пользователи вне аккаунта AWS не смогут просматривать или скачивать файлы.
Эта настройка используется для обеспечения **максимальной безопасности** и предотвращения утечек данных.

#### Создание IAM-пользователя и выдача прав

В этом варианте необходимо создать отдельного пользователя AWS (`s3-uploader`) и дать ему минимальные права работы с бакетами.

Это иллюстрирует, как в AWS разделяют роли и _принципы минимально необходимых прав (Least Privilege)_.

#### Создание пользователя

1. Перейти в `IAM` → `Users` → `Create user`.
2. Создать пользователя с именем `s3-uploader`.
3. `Console access` не включать.
   - Данному пользователю не нужен доступ в консоль, так как он будет работать только через API (CLI/SDK).
4. На странице пользователя → вкладка `Security credentials` → `Create access key`.
   - Тип доступа: `Command Line Interface (CLI)`.
   - Скопировать `Access key ID` и `Secret access key` (понадобятся для CLI).

![image](https://i.imgur.com/k9lzcZj.png)
![image](https://i.imgur.com/rGb2hzw.png)
![image](https://i.imgur.com/0wuJT5l.png)

Такой пользователь используется для автоматизации (CLI, PHP SDK, Python boto3). _Ключи аутентификации_ позволяют безопасно взаимодействовать с AWS-программно,
без использования root-доступа.

#### Создание IAM-политики (минимальные права)

_Политика_ - это JSON-документ, который определяет, какие действия разрешены или запрещены для пользователя.

Цель: дать пользователю `s3-uploader` права на загрузку и чтение объектов в _публичном бакете_ и только чтение в _приватном бакете_.

1. Перейти в `IAM` → `Policies` → `Create policy` → `JSON`.
2. Вставить следующий `JSON`, заменив `kXX` на нужный идентификатор:

```json
   {
     "Version": "2012-10-17",
     "Statement": [
       {
         "Sid": "ListOnlyTheseBuckets",
         "Effect": "Allow",
         "Action": ["s3:ListBucket"],
         "Resource": [
           "arn:aws:s3:::cc-lab4-pub-kXX",
           "arn:aws:s3:::cc-lab4-priv-kXX"
         ]
       },
       {
         "Sid": "ReadWritePublicBucketLimited",
         "Effect": "Allow",
         "Action": ["s3:GetObject", "s3:PutObject", "s3:DeleteObject"],
         "Resource": "arn:aws:s3:::cc-lab4-pub-kXX/*"
       },
       {
         "Sid": "LogsRWButOnlyUnderLogsPrefix",
         "Effect": "Allow",
         "Action": ["s3:GetObject", "s3:PutObject", "s3:DeleteObject"],
         "Resource": "arn:aws:s3:::cc-lab4-priv-kXX/logs/*"
       }
     ]
   }
```

![image](https://i.imgur.com/4ILDeOG.png)

   _При создании политики следует обратить внимание на следующие моменты_:

   - `Version`: версия языка политики (оставить как есть).
   - `Statement`: массив правил.
   - `Effect`: действие правила - `Allow` (разрешить) или `Deny` (запретить).
   - `Action`: список разрешённых действий (например, `s3:PutObject` для загрузки объектов).
   - `Resource`: _ARN (Amazon Resource Name)_ ресурсов, к которым применяется правило. _ARN_ - это уникальный идентификатор ресурса в AWS, каждый ресурс имеет свой ARN. В данном случае, данные правила применяются к нашим бакетом. То есть это значит, что пользователь сможет выполнять указанные действия только с этими бакетами.

   Данная политика позволяет следующее:

   | Раздел                       | Назначение                                             | Объяснение                                                                                       |
   | ---------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
   | ListOnlyTheseBuckets         | Разрешает команду `ListBucket` только для двух бакетов | Без неё пользователь не сможет увидеть содержимое бакета                                         |
   | ReadWritePublicBucketLimited | Полный доступ к публичному бакету                      | Пользователь может загружать, читать и удалять объекты                                           |
   | LogsRWButOnlyUnderLogsPrefix | Даёт доступ только к logs/ внутри приватного бакета   | Пример принципа “минимальных прав”: пользователь не может выйти за пределы разрешённого префикса |

3. Нажать `Next: Tags` → `Next: Review`.
4. Задать имя политики, например, `S3UploaderPolicy`, и нажать `Create policy`.

![image](https://i.imgur.com/xGFDjWF.png)
![image](https://i.imgur.com/mWVj7XU.png)

2. Выберать `Attach policies directly`.
3. Найти и выбрать созданную ранее политику `S3UploaderPolicy`.
4. Нажать `Next: Review` → `Add permissions`.

![image](https://i.imgur.com/22t1r8a.png)

5. Теперь пользователь `s3-uploader` имеет необходимые права для работы с бакетами.
Только теперь пользователь получает доступ к S3. До этого момента AWS по умолчанию всё запрещает ("_deny by default_").

### Шаг 3. Разрешение чтения из публичного бакета

#### Отключение блокировки публичного доступа

По умолчанию все новые бакеты в AWS S3 имеют включённую защиту **Block Public Access (BPA)**, которая запрещает любые публичные действия.
Чтобы включить публичное чтение, необходимо отключить эту блокировку:

1. Перейти в `S3` → `cc-lab4-pub-k01` → `Permissions`.
2. В разделе `Block public access (account settings)` нажать `Edit`.
3. Снять галочку `Block all public access` и подтвердить действие (`Save changes`).

![image](https://i.imgur.com/NrHo1bH.png)

После этого бакет остаётся приватным по умолчанию, но его объекты могут быть открыты для чтения с помощью политики.

#### Создание Bucket Policy для публичного доступа

Затем необходимо добавить политику, которая разрешает публичный доступ на чтение только к нужным каталогам (`avatars/` и `content/`).

1. В том же разделе **Permissions** открыть вкладку **Bucket Policy** и нажать **Edit**.
2. Вставить следующий JSON, заменив `kXX` на ваш идентификатор:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowPublicRead",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": [
        "arn:aws:s3:::cc-lab4-pub-kXX/avatars/*",
        "arn:aws:s3:::cc-lab4-pub-kXX/content/*"
      ]
    }
  ]
}
```

#### Пояснение параметров политики

| Поле          | Назначение                   | Пояснение                                   |
| ------------- | ---------------------------- | ------------------------------------------- |
| **Version**   | Версия формата политики      | Оставляется без изменений (`2012-10-17`)    |
| **Statement** | Массив правил                | Содержит одно правило для публичного чтения |
| **Effect**    | Тип действия                 | `Allow` — разрешает указанные действия      |
| **Principal** | Кто имеет доступ             | `"*"` означает всех пользователей Интернета |
| **Action**    | Разрешённые действия         | Только `s3:GetObject` — чтение файлов       |
| **Resource**  | К каким объектам применяется | Папки `avatars/` и `content/` внутри бакета |

![image](https://i.imgur.com/NkYWoWn.png)
![image](https://i.imgur.com/yMkIgsO.png)

Политика не даёт возможности изменять или удалять объекты, а лишь разрешает их просмотр (скачивание).

3. Сохранить изменения.

Теперь файлы внутри `avatars/` и `content/` будут доступны публично по URL. При этом остальные каталоги бакета по-прежнему закрыты.

### Шаг 6. Включение версионирования объектов (Versioning)

Версионирование в **Amazon S3** позволяет хранить несколько версий одного и того же объекта.
Это полезно при случайном удалении или перезаписи файлов, так как старые версии можно восстановить в любой момент.

#### Включение версионирования

1. Перейти в консоль `S3` → `cc-lab4-pub-k01` → вкладка `Properties`.
2. В разделе `Bucket Versioning` нажать `Edit`.
3. Установить опцию `Enable versioning` и сохранить изменения (`Save changes`).
4. Повторить те же действия для приватного бакета `cc-lab4-priv-k01`.

![image](https://i.imgur.com/j6X9k3n.png)
![image](https://i.imgur.com/knZGq25.png)

После включения в консоли в свойствах бакета появляется статус **“Versioning: Enabled”**.
Теперь при каждой загрузке файла с тем же именем будет сохраняться его предыдущая версия.

#### Проверка работы версионирования

1. Изменить локальный файл `logo.png` (например, добавить штрих или изменить размер).
2. Загрузить обновлённый файл в тот же путь:

```bash
aws s3 cp s3-lab/public/content/logo.png s3://cc-lab4-pub-k01/content/logo.png
```

![image](https://i.imgur.com/WJpN1qq.png)

3. После загрузки открыть бакет → перейти во вкладку `Versions`.
   Там отображаются все версии объекта `logo.png`, каждая с уникальным `Version ID`.

![image](https://i.imgur.com/qLNX8Mq.png)

В бакете теперь хранятся **две версии** файла `logo.png`:

- старая — оригинал (до изменений);
- новая — текущая загруженная версия.

>**Ответ:**
>
>Если версионирование выключить, то **существующие версии сохранятся** и останутся доступными.
Однако **новые версии создаваться больше не будут** — при загрузке файла с тем же именем
он будет **перезаписывать** предыдущий объект без сохранения истории.
При этом полностью отключить версионирование невозможно —
его можно лишь **приостановить (Suspend)**, но не удалить уже существующие версии.

### Шаг 7. Создание Lifecycle-правил для приватного бакета

В **Amazon S3** можно автоматизировать процесс управления жизненным циклом данных с помощью **Lifecycle-политик**.
Они позволяют автоматически перемещать (архивировать) объекты между различными классами хранения в зависимости от возраста,
а также удалять устаревшие файлы через определённый срок.

#### Создание правила жизненного цикла (Lifecycle rule)

1. В приватном бакете необходимо зайти в `Management` → `Lifecycle rules` → `Create rule`.
   - Имя: `logs-archive`
   - Префикс: `logs/`
   - Actions:
      - `Transition → Standard-IA` через 30 дней
      - `Transition → Glacier Deep Archive` через 365 дней
      - `Expiration → удалить` через 1825 дней (5 лет)
2. Сохранить правило: `Create rule`.

![image](https://i.imgur.com/fFcn4CJ.png)
![image](https://i.imgur.com/l6eIqgf.png)
![image](https://i.imgur.com/nNAtKJG.png)

После создания правило автоматически применяется ко всем объектам с префиксом `logs/` внутри бакета `cc-lab4-priv-k01`.
Теперь логи будут автоматически перемещаться между классами хранения в зависимости от времени, прошедшего с момента загрузки.

> **Вопрос:**
>
> Что такое Storage Class в Amazon S3 и зачем они нужны?
>
>**Ответ:**
>
>Storage Class (класс хранения) — это уровень хранения данных в S3, который определяет:
>
>- **скорость доступа** к объектам,
>- **стоимость хранения** и **восстановления**,
>- и предназначение данных (часто, редко или архивно используемые).
>
>Каждый класс хранения оптимизирован под определённый сценарий:
>
>- **S3 Standard** — для часто используемых данных;
>- **S3 Standard-IA** — для редкого доступа при сохранении высокой доступности;
>- **S3 Glacier / Deep Archive** — для долговременного архивирования;
>- **S3 Intelligent-Tiering** — автоматически выбирает оптимальный класс в зависимости от частоты обращений.
>
>Классы хранения позволяют **уменьшить стоимость** за счёт перемещения старых или редко используемых данных в более дешёвые хранилища.

### Шаг 8. Создание статического веб-сайта на базе S3

В сервисе **Amazon S3** можно разместить статический веб-сайт без использования серверов — файлы просто хранятся в бакете и доступны через HTTP.
Такой подход удобен для публикации простых HTML-страниц, портфолио, документации или собранных React/Vue-приложений.

#### Создание бакета для веб-сайта

1. Необходимо перейти в `S3` → `Create bucket`.

2. Задать параметры:

- Имя: `cc-lab4-web-kXX`
- Region: `eu-central-1`
- Object Ownership: ACLs enabled (Can be configured using ACLs)
- _Block all public access_: снять галочку (разрешить публичность)
- Нажмите `Create bucket`

После создания настроить хостинг:

1. Необходимо перейти в бакет → вкладка `Properties` → `Static website hosting` → `Edit` -> `Enable`.
2. Выбрать следующие параметры:

   - _Hosting type_: `Host a static website`.
   - _Index document_: `index.html`.

2. Все объекты необходимо сделать **публичными** (через `Make public`).
3. После загрузки перейти по выданному URL и убедиться, что сайт открывается.
4. Открыть URL статического сайта, указанного в настройках S3.
